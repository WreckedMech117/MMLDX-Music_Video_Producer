  - **Keyed by Shot id, never by position.** A prompt is free text, so a positional merge after a concurrent add, delete or split writes a plausible prompt onto the wrong Shot and nothing downstream fails. A route test commits a Shot insertion while the model call is in flight and asserts every prompt still landed on the Shot it was addressed to.
  - **Song-section input is an explicitly empty branch, not an analyser.** FR-26 asks for section boundaries "when analysis exists" and no analysis exists anywhere in this project — no BPM or section field on `Song`, `Project` or `Shot`, a disabled analyse-structure button, hardcoded "Not analyzed" readouts, and a `#section-track` that is never populated. `timeline.song_section` is one named empty branch; the key is **omitted** rather than sent as `""` or `"unknown"`, and a test asserts both the absence and that no data source for it exists. `song_fraction` is absent the same way when there is no Song or its duration is 0, because a fabricated 0.0 would tell the model every Shot opens the song.
  - **Nothing is rendered and nothing is retimed.** The route never touches `comfy`, never advances a Shot's `status`, and assigns only `prompt`; tests assert `comfy.prompts` stays empty and that every window is unchanged. Window checks here are **descriptive flags** on the input, not a gate — expansion writes prompts, so nothing new can fail. Prompt quality is Story 2.3's readiness gate and is deliberately not blocked on here.
  - **The model's input is purpose-built and trimmed.** `timeline.expansion_input` is pure and I/O-free and carries no `status`, `prompt_id`, `latest_output`, `latest_review` or `approved_output` — the recorded root cause of Director degradation is rich context. A test asserts the route hands that builder's output to `expand` **verbatim**, which is what makes "the input includes each Shot's position in the song" falsifiable at all.
  - **Reported, never guessed.** A returned id matching no Shot is discarded and named; a Shot the model omitted keeps its prompt and is named; a prompt that parses as JSON is refused by the same `document_rejection` check FR-15 added and named. None of the three is retried and none creates a Shot — if the Director wants omissions retried or unknown ids created, that is a different design.
  - **Not driven in a real browser.** The Treatment workspace's "Expand shots into prompts" button (`#expand-shot-prompts`, built over what was the disabled `#apply-shot-plan` stub) has offline contract tests only; only the executable contract is claimed for the UI half.

Update this document whenever a live verification changes readiness.
