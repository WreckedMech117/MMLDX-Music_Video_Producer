Promotion had never run from the app either. Two GPU jobs were authorised and exactly two were spent.

- **What ran.** ComfyUI 0.33.1 at `127.0.0.1:8188`, app on port 8766 with an isolated data root, project `project_9d237e8fbddb`, 2026-08-18. `tests/preflight_h3_ultra.py` first: `OK 138 nodes across 8 variants (18 classes)`. The run measured 90 and 3.750 s, so the grid arithmetic holds at a second point on it. - **The probe target is chosen by name.** A completed H3 shot leaves a `.png`, a silent `.mp4` and a muxed `-audio.mp4`, and only the last carries synchronized audio. This run's `output_files` happened to carry only the `-audio.mp4`, so the file chosen by name and the file `latest_output` received were the same — but that is a measurement, recorded as one, not a property to rely on. `output_files[0]` remains the app's own choice and this run does not license it.

The emitted audio is 3.744 s. Before this run nobody knew whether a long master forced the whole track through the audio VAE.

- **An unresolved observation, recorded without a cause.** The first frame shows the Reference Sheet's four-panel layout carried into the *composition*: the face plate visible on the left, the vertical panel bands persisting, a figure standing inside one band. The model appears to have treated the sheet's layout as scene structure rather than purely as identity reference. Two factors plausibly contribute and neither is established — 4 steps is far below anything usable, and `ref_image_size` was `"match"` (the default), so the 1536×1024 sheet was conditioned at its own aspect. Whether a production step count, `"max"` sizing, or a single-view reference changes it is untested. Filed as deferred work.

Epic 3's goal — "a character recognizably the same person across the Shots of a finished video, judged by the Director's eye" — is **not** demonstrated by this run, and one 4-step clip could not demonstrate it even if it looked perfect.

## 2026-08-17 — A protective refusal that cannot be mistaken for a reply

Closed under `spec-2-4-director-safety-notices-unmissable.md`; the binding decisions are AD-14 and AD-5 in `ARCHITECTURE-SPINE.md`. Every refusal this project produces was concatenated into the assistant message as plain text after a `\n\n---\n` separator. Nothing rendered it distinctly, no test touched the thread render at all, and the document-rejection notice — the only one with no named constant — embedded up to 400 characters of the model's degraded output straight into `content`. The chat thread is dumped back to the model as context on the next turn, so the guard written to stop "JSON in context begets JSON" was the thing supplying it. Story 2.2 closed that loop for expansion by dropping the refused text entirely; the chat route still had it open. FR-15's prose-claims-Shots clause had no implementation anywhere.

- **Structure instead of a text convention.** `models.MessageNotice` carries a display `text` and the `raw` model output it is about; `TreatmentMessage.notices` is a defaulted list of them, so a manifest written before this loads unchanged and simply carries none. `content` keeps carrying the joined text — it is what every saved project already holds and what `api.js`'s two marker-scanning helpers read, and changing it would break both for no gain.
- **`DIRECTOR_CONTEXT_EXCLUDE` drops the whole `notices` list, not the `raw` field inside it.** Every notice's sentence is already in `content`, so keeping the structured copy would echo a second copy of each notice into the prompt — the same objection that put the recovery slots in this mapping. And a nested exclusion path silently stops covering a field that is renamed or added beside it, which is not a property to want on the one invariant that turns the degradation guard into the source of the degradation.
- **Asserted against the recorded context, not the stored message.** Two route tests refuse (chat, then expansion), take a further chat turn, and read the `project_context` the double was actually handed. The containment check walks the payload's strings instead of searching `json.dumps`: `json.dumps` escapes the quotes that degraded model output is made of, so `'[{"style":"moody"}]'` is never a substring of a dump containing it — the previous assertion passed whether or not the text was there, which is exactly the class of green-suite inversion this story exists to end.
- **The expansion route's refused prompt is restored into `raw`**, which was the spec's one "ask first". Story 2.2 dropped it only because there was nowhere to put it that the next call would not read; the excluded field is that place. `EXPANSION_REJECTED_NOTICE` claimed in its own words that the text was not recorded, so that sentence was rewritten rather than left to become a lie the tests still asserted.
- **No splitting on `---`, and the test proves the shortcut would have been wrong rather than merely forbidding it.** The Director's prose can contain that sequence and so can the raw output a notice embeds — which would split one notice into two blocks, the second being the model's own degraded text presented as a protective refusal. `messageParts` reconstructs the exact tail the server joined and strips it; the fixture's model message deliberately contains `\n\n---\n`, and the test asserts the naive split really does lose most of it. A message whose tail the client cannot account for keeps all of its content and still shows every notice: printing one twice is visible, swallowing half a refusal is not.
- **One separator, typed once.** `NOTICE_SEPARATOR`/`NOTICE_JOIN` and one `assistant_reply` helper replace the byte-identical literals both routes carried, and `api.js` exports the same two constants with a contract test asserting they are identical — the `READINESS_REFUSAL` pattern.
- **FR-15's last clause, implemented.** A reply whose prose describes a shot plan while the structured list is empty is reported as a mismatch. Ungated on `apply_shots`: the browser hardcodes that flag to `false`, so gating it there would put the notice exactly where the existing empty-shot-list notice already is — unreachable. Detection is two narrow patterns, the word itself and a counted structure, because the recorded 2026-08-16 defect never used the word "shot": it said "Splitting your vision into a four-beat sequence", and a check that misses the one recorded instance of the defect is not a check. It reports and never blocks — with no shots there is nothing to apply, so a false positive costs a paragraph and a false negative costs the Director a plan they believe exists. The two empty-list notices stay independent and can both fire: one says the reply contradicts itself, the other says the consent given produced nothing.
- **The collapse floor now runs through the route.** It had four unit tests and no request had ever reached it, because every double either echoed the stored document or returned a long replacement — the route could have stopped consulting `document_rejection` for short candidates with a fully green suite.
- **Unmissable is a label plus an edge, never an edge alone.** Each notice renders in its own block with the existing `--amber` caution token on the left border — no new colour — a text label above the sentence, and the raw output behind a `<details>` collapsed by default. `escapeHtml` moved into `api.js` so the whole message body is one pure export: the thread was a single `innerHTML` map that escaped `content` whole, so notice markup had to be built by splitting *before* escaping each part.
- **The render is executed, not grepped.** `messageParts` and `messageBodyHtml` run under node against a reply the live route produced, and the assertions read the HTML the browser would get: two blocks, one label each, exactly one closed disclosure, the fixture's `<script>` tag escaped, and each notice printed exactly once. Story 2.3's review found three UI guarantees pinned only by substring matching that could invert with a green suite; a substring of `app.js` proves the source contains a string, not that a notice renders.
- **Twenty-four mutations reintroduced. All twenty-four caught on the first attempt, and every file was restored byte-identical afterwards.** The exclusion dropping `notices`; `raw` emptied on either route; the raw pasted back into `content`; the mismatch notice deleted, or gated on `apply_shots`; the claim patterns narrowed to the literal word, or widened to fire on everything; the consent notice suppressed by the mismatch; the reply built without the shared helper; `MIN_REPLACEMENT_RATIO` zeroed; `notices` made required so an old manifest fails to load; the splitter searching for the separator, or leaving the joined tail in the prose; the label dropped; the disclosure opened by default; the raw interpolated unescaped; the notices rendered before the prose; `renderTreatment` reverting to escaping `content`; the amber becoming a literal hex; a later rule reclaiming the notice edge; the notice paragraph rule dropped; and `_raw_excerpt` left uncapped.

## 2026-08-17 — A Shot Plan that cannot be submitted unprompted

Closed under `spec-2-3-shot-plan-readiness-gate.md`; the binding decision is AD-5 in `ARCHITECTURE-SPINE.md`. An empty-prompt Shot reached ComfyUI and burned a full GPU pass to return noise. `generate_h3` checked only `status == "ready"` and never looked at the prompt; the text branch submitted `"local_prompts": ""` without complaint; `compile_timeline` serialised `"prompt": ""` in silence. Nothing anywhere computed whether a plan was fit to submit, and nothing noticed that two Shots carried the same prompt.

- Added `src/music_video_producer/batch.py` with one pure `readiness_report(project)` — AD-5's module, and deliberately the module Epic 4's batch submission, submission ordering and reconciliation will grow into. It is the *single* implementation on purpose: the route, the browser's pre-batch check and the pre-flight Story 4.2 will build all ask the same question, and three implementations of "is this plan fit to render" is three chances for a pre-flight to say yes to something the route then refuses.
- **Emptiness blocks and names the Shots; sameness warns and never blocks.** Whitespace-only counts as empty, matching `expansion_rejection`'s `if not prompt.strip()` — ComfyUI cannot tell three spaces from `""`, and both cost the same GPU minutes. Near-duplicates are reported in two distinct sentences rather than one: prompts equal after lowercase and whitespace collapse are *identical*, and prompts sharing more than 90% of their tokens are *similar*. Telling a Director that `"A Shot"` and `"a   shot"` are merely similar sends them looking for a difference that is not there. Sameness will never block: a repeated beat can be a deliberate choice, and a gate that refuses one is a gate that gets worked around.
- Overlap is **Jaccard** — shared tokens over the tokens of the pair — not intersection-over-smallest, which scores a one-line prompt fully contained in a paragraph as a perfect duplicate. The threshold test is written against a pair sharing 10 of the 11 tokens it spans (0.909) and a pair sharing 8 of 10 (0.8), so it asserts the threshold rather than "these two look alike".
- **A blocked Shot is never also reported as a duplicate.** Two empty prompts are trivially identical; saying so buries the entries that have to be acted on under a warning that resolves itself the instant either one is.
- **The guard reads `shot.prompt`, at the route, before the payload — and this is the whole design.** `app.py` builds `f"Reference map: {tags}. {shot.prompt}"` for the reference branch, so an empty prompt arrives downstream as a populated sentence and every truthiness check past that line passes on exactly the Shots the gate exists to catch. A guard placed in the payload builder, or one line lower in the route, would let through the most expensive path in the application. Two route tests replace the payload builders with a function that raises and assert the 422 still comes back, on the text branch and the reference branch, in identical words.
- **The gate is not keyed to `Shot.status`, and is checked before the status check.** Nothing in the shipped frontend ever writes `ready` — new Shots and duplicates are `draft` — so `"Shot must be ready before H3 submission"` is reachable only from a hand-rolled client, and a readiness gate keyed to status would inherit that dead end. Ordering the readiness refusal first also means an unprompted draft is told the real problem instead of being told to change its status, which is neither actionable nor true.
- **Derived, never stored.** No new `Shot` field and no persisted flag: a stored `ready` is a second source of truth that goes stale the moment a prompt is edited. Tests assert the manifest is byte-identical after a report and after the new `GET /api/projects/{id}/readiness` route. `flagged` state is a later decision and is deliberately not started here.
- **The dry run reports and does not block.** That was the spec's one open question. `compile_timeline` queues nothing and costs nothing, so refusing it would remove the one cheap way to see what a plan would serialise — and what it serialises for a blank Shot is `"prompt": ""`, which is precisely the thing worth seeing before the expensive call. Its response now carries a `readiness` block and still compiles an unprompted plan.
- **Best-effort against a half-submitted batch — not a guarantee, and review corrected the first wording, which claimed one.** The queue-ready handler asks the server for readiness once, before its loop: the route refuses per submission, so a refusal discovered mid-loop leaves every earlier Shot already queued and burning GPU minutes on a plan that is about to be edited and resubmitted. What the pre-loop check cannot close is the window between the check and the last submission — a prompt blanked in a second tab, by a Director turn, or by the expansion route lands the batch exactly where it started. A direct API caller gets per-Shot semantics and no batch behaviour at all. The real fix is AD-5's server-side batch endpoint in Epic 4; this is the client-side approximation of it. Only Shots actually in the batch can block it — refusing over a blank draft elsewhere in the plan would make the button unusable for any plan still being written, which is every plan, most of the time. The GPU-cost confirm moved *after* the check, so nobody is asked to accept a cost for a batch that was never going to be sent.
- **One refusal wording per layer**, in the pattern the song refusal and the expansion refusal already use: `batch.READINESS_REFUSAL` and `api.js`'s `READINESS_REFUSAL` are asserted identical under node, and `promptIsMissing` is asserted to agree with `prompt_is_missing` on `""`, on whitespace, on a real prompt, and on a shot object with no prompt field at all — the timeline redraw runs it on every drag and must never throw. The shared constant is deliberately ASCII: node's stdout is decoded with the platform encoding on Windows, and a typographic dash would come back mangled and fail the test that holds the two wordings together for the wrong reason.
- **Emptiness is visible before the click.** The timeline clip rendered `shot.prompt || "Untitled shot"`, which is exactly what a real prompt reading "Untitled shot" renders, so the one state that costs a wasted GPU pass looked identical to a named shot. It now renders `NO PROMPT` and carries a dashed border — two signals, because state is never conveyed by colour alone, matching the `.job-status` precedent. **No pre-flight modal**: that surface is Epic 4 (Story 4.2), and this ships the backend gate it will consume.
- `timeline.py` does not import `batch.py` and a test asserts it. The reverse import would not fail — Python would resolve it — it would simply make the two mutually dependent, and everything else AD-5 puts in `batch.py` (submission ordering, orchestration, ComfyUI reconciliation) would then be dragged into the one module that is pure window math.
- Added twenty-five tests: fourteen in a new `tests/test_batch.py` covering every I/O matrix row directly over the pure report (the `tests/test_timeline.py` precedent), six route tests in `tests/test_api.py`, and five in `tests/test_frontend_contract.py` — including one that enumerates every `comfy.submit` call site off the live app, pins the set of five, and asserts each Shot-sourced one guards before it submits *and* before the reference interpolation. Pinning the set is what makes a future submitting route a decision rather than an omission.
- Review then found substantially more, and closed it in a second pass. **The app's own `"New shot"` placeholder walked straight through the gate** — all three reviewers found it, and the project's own fixture proved it by counting a placeholder Shot as ready. `prompt_rejection` now returns a distinct reason for the placeholder, compared after case-and-whitespace collapse so a spaced copy is caught while `"New shot on the corridor…"` is not. Also closed: `_tokens("")` returned a phantom empty-string token that participated in every intersection, making the empty-set guard unreachable; tokenising on whitespace alone meant `"A singer turns."` and `"A singer turns"` were neither identical nor similar; the exact 0.9 threshold was untested, and the fixtures that claimed to test it repeated a word, so their arithmetic was wrong; `readiness_refusal([])` rendered "no prompt on ."; the refusal named raw ids the interface never shows, so notes now carry `SHOT 01 (id)` labels numbered the way the timeline draws them, capped at five with "and N more"; and the route recomputed an O(N²) pairwise scan per submission purely to build warnings it discarded, so callers can now ask for a blocking-only report, with `warnings_computed` distinguishing "none found" from "not looked for". A client that omits the field, or sends it as `null`, is read as a decline. ## 2026-08-17 — FR-12 import duration regression guard, and the frontend defect it found

Closed under `_bmad-output/implementation-artifacts/spec-1-3b-import-duration-regression-guard.md`. FR-12 was listed as verified, but the verification only covered the server. Writing the missing frontend guard turned up a real defect.

- Found the defect: the browser defeated the server's own ffprobe fallback. The `#song-file` change handler toasted on a failed decode but never cleared `state.audioBuffer`, and the import handler sent `state.audioBuffer?.duration || 0`. So importing an undecodable file into a project that already had a decodable song sent the **previous song's** duration; `app.py`'s `resolved_duration = duration if duration > 0 else _media_duration(target)` saw a non-zero value, ffprobe never ran, and a wrong length was persisted. Song duration is the timing spine every Shot window, playback sync, and Assembly derives from, so a wrong value is worse than a missing one.
- Fixed it in two places. The decode-failure path now nulls `state.audioBuffer`, re-renders, and resets the displayed duration to `—`, so nothing survives a failure that could be mistaken for a measurement of the new file. The sent value now comes from a pure exported `songImportDuration({ decoded })` in `api.js`, which returns 0 for a missing buffer and for any non-finite or non-positive duration, and ignores every other piece of state handed to it.
- Also corrected a display bug in the same handler: the success path set `#duration-value` and *then* called `renderSong()`, which immediately overwrote it with the previously loaded project song's duration. The two statements are now ordered so the newly chosen file's length is what stays on screen.
- Added four collected tests, each mutation-checked by reintroducing the defect and confirming the test fails. Two in `tests/test_frontend_contract.py`: the pure decision executed under the node harness (a decodable buffer sends its length; a failed decode sends 0; a failed decode **with a prior buffer present** still sends 0, plus the NaN/Infinity/negative/zero shapes), and a source-level companion pinning that the handlers drop the buffer and delegate rather than reading the duration raw. Two in `tests/test_api.py`: an upload with `duration=0` into a project that already holds a 187.5 s song, re-read through a **fresh `ProjectStore`** over the same data root to prove the probed value reached the manifest and replaced the old one — the previous route test only inspected the response body, which is the in-memory object the handler had just built — and an ffprobe-unavailable case that patches `subprocess.run` to raise `FileNotFoundError` for `ffprobe` only, asserting the import still succeeds and stores 0 rather than a fabricated number.
